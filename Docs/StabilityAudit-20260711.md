# Universal Device Toolkit 稳定性审计报告（2026-07-11）

## 1. 审计范围

本轮审计覆盖 Release x64 构建、主测试套件、跨平台测试、语言包/网络/发布载荷关键路径、CLI、启动窗口、Windows 清理、通知默认值、视觉回归工具、插件 UI 冒烟以及残留进程检查。测试期间保留当前未提交的品牌、网络代理、灯效、语言包、通知和自动化修改；未提交、未重启，也未执行危险硬件恢复或功耗写入。

## 2. 总体结论

- **代码级稳定性：通过。** Release x64 解决方案构建为 0 警告、0 错误。
- **自动化测试：通过。** 主测试 4,436 通过、30 跳过、0 失败；跨平台 137/137 通过；关键语言/网络/发布测试 42/42 通过。
- **启动可用性：通过。** 隔离配置下主窗口可显示、导航侧栏两态可切换，未观察到 UDT、代理或冒烟工具残留进程。
- **视觉/插件冒烟：部分通过。** 主窗口、侧栏展开/折叠和 Dashboard 已成功捕获；后续流程仍受冒烟工具对本地化标题、独立插件设置窗口和截图瞬态的旧假设影响，不代表产品崩溃。
- **硬件相关验收：有条件通过。** 未在本轮自动写入 EC、GPU、风扇、功耗或显卡模式；需要管理员权限和真实设备能力的预设验证仍应在受控人工环境完成。

## 4. 已发现并修复的问题

### 4.1 通知默认位置测试过期

两个测试仍断言 `BottomCenter`，与产品全局右下角通知策略冲突。已统一为 `NotificationPosition.BottomRight`。

### 4.2 启动语言窗口布局守卫过期

语言下载失败界面新增“重试 / 继续英文 / 退出”后高度为 300px，守卫仍按 245px 判断。已更新守卫。

### 4.3 新 UI 存在英文硬编码

修复语言下载失败按钮、通知关闭、传感器分区窗口、电池百分比触发器和硬件传感器触发器中的英文硬编码；新增资源键、简体中文资源和强类型访问器。聚焦回归 49/49 通过。

### 4.4 Windows 清理测试扫描真实用户目录导致挂起

`EstimateCleanupSizeAsync_ShouldReturnNonZeroForValidActionKey` 会递归扫描真实 `%TEMP%`，超过 120 秒并触发 testhost dump。现在 `WindowsCleanupService` 支持注入环境路径解析器，生产默认行为不变，测试只扫描受控临时目录，耗时约 59ms。

### 4.5 安装器语言所有权测试过期

测试仍验证旧版静默回退调用。已改为验证 `LanguageGateOutcome`、重试、继续英文和禁止静默回退的新链路。

### 4.6 视觉冒烟侧栏判定错误

旧工具通过导航项边界估算宽度，紧凑态会得到 60/77px 的假差异。已改为使用内容区边界测量真实两态，并等待动画稳定；实测展开约 305px、折叠约 118px、恢复约 305px。

### 4.7 冒烟工具与当前架构脱节

- 视觉工具原先强制 IPC 就绪，即使 UI Automation 已可用；现改为视觉捕获时 IPC 可选。
- 通用/基础设备没有键盘导航项时不再失败；仅显式传入 `--expect-keyboard-navigation` 才要求该能力。
- 插件工具不再要求每个插件同时具有 Marketplace Open 和重复侧栏入口。
- 页面到达判定增加标题和本地化导航名称支持。

## 5. 剩余风险

### 高优先级

1. **IPC 在隔离视觉启动中 30 秒内未就绪。** UI 可用，但应继续检查安全启动下 IPC 服务是否被故意跳过、命名管道名称是否一致，或初始化是否被某个后台步骤延迟。
2. **插件 UI 冒烟对独立设置窗口识别不完整。** Custom Mouse 已打开独立设置窗口，但工具仍以 Marketplace 搜索框是否消失判断“离开页面”，导致误报和长等待。
3. **截图工具存在窗口抢焦点/全白帧竞态。** 一次截图捕获到其他前景窗口的白色内容；应按目标 HWND 捕获并增加非空帧重试，而不是依赖屏幕矩形。

### 中优先级

1. 管理员预设 UI 验证尚未执行。
2. 在线语言包真实下载仍依赖发布端点、签名和网络环境；当前只验证了代码与测试模拟链路。
3. 网络代理需要补充真实 HTTP、CONNECT、端口占用、代理崩溃和系统代理精确恢复的管理员集成测试。
4. 24 区键盘、环境灯、GPU/EC/风扇等能力仍需对应硬件矩阵验证。

## 6. 稳定性改进建议

1. 所有测试禁止默认扫描真实用户目录、注册表或系统网络状态；统一注入文件系统、环境变量和系统设置适配器。
2. 为所有集成/冒烟步骤设置单步超时和总预算，并在超时时自动保存截图、自动化树、进程列表和应用日志。
3. UI 冒烟应以设备能力为条件，不应假设键盘、灯效、GPU、插件侧栏入口始终存在。
4. 将 IPC 健康检查拆为“UI 可用”“后台服务可用”“硬件初始化完成”三个独立状态，避免一个状态阻塞全部视觉验证。
5. 插件冒烟同时跟踪主窗口与独立设置窗口，按 AutomationId/进程/窗口标题确认成功，不再用 Marketplace 搜索框作为唯一状态。
6. CI 增加：Release x64 单进程构建、完整测试、资源审计、XAML 守卫、CLI smoke、无管理员视觉 smoke；管理员与硬件测试进入独立受控流水线。
7. 对启动初始化记录每步骤耗时、超时、取消和安全启动原因，构建 P50/P95 启动时延趋势，防止卡顿回归。

## 7. 发布建议

当前版本满足“可构建、主测试全绿、隔离安全启动显示主窗口、无残留进程”的代码合并门槛。正式发布前建议完成管理员预设验证、真实在线语言包下载、网络代理恢复集成测试，以及至少一台支持设备上的 EC/GPU/风扇/灯效人工验收。
